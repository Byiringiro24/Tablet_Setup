# WireGuard VPN Setup Guide — Server and Tablet

**EcaAfrica Attendance System**
Last updated: September 2026

---

## Overview

WireGuard creates an encrypted tunnel between the school server and each attendance tablet.
Once connected, the server can pull attendance logs from the FK623 device through the tablet
automatically — no manual intervention needed.

```
FK623 Device ←→ Tablet (Windows) ←→ WireGuard VPN ←→ Server (169.58.124.150)
                 10.0.0.x                                10.0.0.1
```

- Server VPN IP: **10.0.0.1** (always fixed)
- Tablets get IPs: **10.0.0.2, 10.0.0.3, 10.0.0.4 ...** (one per tablet, up to 65,534)
- WireGuard port: **51820 UDP**

---

## Part 1 — Server Setup (one time only)

This is done once when the server is first configured. After this, every new tablet
is added through the Super Admin portal — no SSH needed.

### 1.1 Install WireGuard on the Server

SSH into the server:
```bash
ssh root@169.58.124.150
```

Install WireGuard:
```bash
apt update && apt install -y wireguard wireguard-tools
```

### 1.2 Generate Server Keys

```bash
# Generate private key
wg genkey > /etc/wireguard/server_private.key
chmod 600 /etc/wireguard/server_private.key

# Derive and save public key
cat /etc/wireguard/server_private.key | wg pubkey > /etc/wireguard/server_public.key

# Show the public key — you will see this in the Super Admin portal
cat /etc/wireguard/server_public.key
```

Example output:
```
6b8yTx1nz243Z044DZTt/OP5+gdLj9lVmUr5DteDzko=
```

### 1.3 Create the WireGuard Interface Config

```bash
cat > /etc/wireguard/wg0.conf << EOF
[Interface]
PrivateKey = $(cat /etc/wireguard/server_private.key)
Address = 10.0.0.1/16
ListenPort = 51820

# Tablet peers are added below by the Super Admin portal
# Do not edit this file manually after this point
EOF
```

> **Important:** The subnet is `/16` (not `/24`). This supports up to 65,534 tablets.

### 1.4 Start WireGuard and Enable Auto-Start

```bash
# Start the interface
wg-quick up wg0

# Enable on boot
systemctl enable wg-quick@wg0

# Verify it is running
wg show
systemctl status wg-quick@wg0
```

Expected output from `wg show`:
```
interface: wg0
  public key: 6b8yTx1nz243Z044DZTt/OP5+gdLj9lVmUr5DteDzko=
  private key: (hidden)
  listening port: 51820
```

### 1.5 Open the Firewall

```bash
# Allow WireGuard UDP traffic
ufw allow 51820/udp

# Allow the backend API port
ufw allow 5500/tcp

# Check status
ufw status
```

If UFW is not enabled (status: inactive), the firewall is not blocking anything —
WireGuard is accessible. You do not need to enable UFW if the VPS provider
handles firewall rules.

### 1.6 Verify Server Setup

```bash
# All of these should pass
wg show                          # shows interface wg0 with public key
systemctl is-active wg-quick@wg0 # prints "active"
cat /etc/wireguard/server_public.key  # prints the public key
ss -ulnp | grep 51820            # shows UDP socket listening on 51820
```

## Part 2 — Adding a New Tablet (Super Admin Portal)

This is done for every new tablet. No SSH required after Part 1.

### 2.1 Open the VPN Setup Tab

1. Log in as Super Admin at `https://ecareafrica.net`
2. Go to **Hardware** in the left menu
3. Click the **VPN Setup** tab

You will see two panels:

- **Step 1 — Server Info**: shows the server public key, endpoint, and next available VPN IP
- **Step 2 — Register Tablet**: paste the tablet public key here

### 2.2 Note the Server Info

From the Step 1 panel, note down:
- **Server Public Key** — e.g. `6b8yTx1nz243Z044DZTt/OP5+gdLj9lVmUr5DteDzko=`
- **Server Endpoint** — e.g. `169.58.124.150:51820`
- **Next Available VPN IP** — e.g. `10.0.0.3`

Click the **Copy** button next to each value. You will paste these into the tablet wizard.

## Part 3 — Tablet Setup (Tablet Web Interface)

This is done on each tablet. Open a browser on the tablet and go to:
```
http://localhost:3000
```

Click the **WireGuard VPN** button in the sidebar (bottom left). Enter the admin password when prompted.

### Step 1 — Install WireGuard

The wizard checks if WireGuard is installed.

**If not installed:**
1. Click **Download WireGuard for Windows** — opens wireguard.com
2. Download and run the installer (`wireguard-installer.exe`)
3. Accept the UAC (admin) prompt
4. Come back and click **Check Again**
5. The status changes to green — click **Next**

**If already installed:** Click **Next** directly.

> **Important:** The bridge app (`server.js`) must be running as **Administrator**
> for WireGuard to work. If you see a yellow warning saying "Bridge is not running
> as Administrator":
> 1. Close the current Node/bridge window
> 2. Right-click the bridge shortcut
> 3. Click **Run as administrator**
> 4. Refresh the browser page

### Step 2 — Generate Keys

1. Click **Generate Keys**
2. The tablet creates a private key (saved locally, never shared) and a public key
3. Click **Copy** next to the public key
4. Go to the Super Admin portal (Part 2.2) and paste this public key in the
   **Step 2 Register Tablet** panel
5. Enter the assigned VPN IP (from Step 1 panel, e.g. `10.0.0.3`)
6. Add an optional label (e.g. `Green Hills Tablet 1`)
7. Click **Add Peer to VPN** — the server registers this tablet

After clicking Add Peer, the portal shows a green success box with:
- Server Public Key (copy it)
- Server Endpoint (copy it)
- Assigned VPN IP (copy it)

Come back to the tablet wizard and click **Next → Configure**.

### Step 3 — Configure

Paste the three values from the portal:

| Field | Value | Example |
|---|---|---|
| Server Public Key | From portal Step 1 | `6b8yTx1nz...ko=` |
| Server Endpoint | From portal Step 1 | `169.58.124.150:51820` |
| Tablet VPN IP | From portal Step 2 success box | `10.0.0.3` |
| DNS Server | Leave as default | `1.1.1.1` |

The config preview updates live as you type. When it looks correct, click
**Save & Activate Tunnel**.

**If activation succeeds:** The wizard moves to Step 4 automatically.

**If activation fails with a GUI import message:**
1. Open the **WireGuard app** on the tablet (search "WireGuard" in Start menu)
2. Click **Import tunnel(s) from file**
3. Navigate to the path shown in the error message (usually `C:\Temp\EcareAfrica.conf`)
4. Select the file and click **Open**
5. Click **Activate** in the WireGuard app
6. Come back to the wizard and click **Step 4**

### Step 4 — Tunnel Status

The wizard shows the tunnel state:

- **Green "Tunnel Active"**: handshake has been established — proceed to Step 5
- **Amber "Tunnel Inactive"**: handshake not yet established

If inactive, check:
1. Did you complete Step 2.2 (Add Peer) in the Super Admin portal?
2. Is the server public key pasted correctly in Step 3?
3. Is the VPN IP correct and matching what the server assigned?

Click **Refresh** to update the status. Once green, click **Test Connection →**.

### Step 5 — Ping Test

1. The target IP is pre-filled as `10.0.0.1` (the server VPN IP)
2. Click **Ping**
3. The tablet sends 4 ICMP packets through the VPN tunnel to the server

**If ping succeeds (green):**
- The VPN tunnel is live and encrypted
- The school server will detect this tablet within 30 seconds
- Attendance logs will be pulled automatically
- Click **Close — Tablet is ready**

**If ping fails (red):**

| Cause | Fix |
|---|---|
| Tunnel not active | Go back to Step 4, click Re-activate |
| Server peer not added | Go to Super Admin portal, add the peer |
| Wrong server public key | Go to Step 3, re-paste the correct key |
| Server firewall blocking | Run `ufw allow 51820/udp` on server |
| Server WireGuard down | Run `systemctl restart wg-quick@wg0` on server |

## Part 4 — Verify from Server (Optional)

After the tablet pings succeed, you can confirm from the server side:

```bash
# Check which tablets are connected
wg show

# Look for the tablet's public key with a recent handshake:
# peer: EsODCoT8KkN21mY6oq1BKsr50NHgUwfPLHH893978W0=
#   endpoint: 102.22.140.197:40768
#   allowed ips: 10.0.0.3/32
#   latest handshake: 1 minute, 2 seconds ago    ← this means connected
#   transfer: 308 B received, 92 B sent

# Ping the tablet from the server
ping -c 4 10.0.0.3

# Try to reach the tablet bridge app
curl http://10.0.0.3:5000/api/health
```

## Part 5 — Registering the Tablet in EcaAfrica

After the VPN tunnel is live, register the tablet in the system:

1. Go to Super Admin → **Hardware** → **Tablets** tab
2. Click **Add Tablet**
3. Fill in:
   - **Name**: e.g. `Green Hills Tablet 1`
   - **IP Address**: the tablet's VPN IP (e.g. `10.0.0.3`)
   - **Port**: `5000`
   - **Location**: e.g. `Main Gate`
4. Click **Save**
5. Click the **ping** icon to verify the tablet is reachable
6. Click **Connect** to link the FK623 device

Once connected, the server will automatically:
- Pull attendance logs every 5 seconds (pull-logs job)
- Receive real-time scans via SSE within 1 second (bridge-sse job)
- Record boarding attendance if device is set to boarding mode

## Part 6 — Adding More Tablets

For each additional tablet, repeat **Parts 2 and 3** only. Part 1 (server setup) is
done once and never needs to be repeated.

Each tablet gets a unique VPN IP:
- Tablet 1: `10.0.0.2`
- Tablet 2: `10.0.0.3`
- Tablet 3: `10.0.0.4`
- ...and so on

The Super Admin portal shows the next available IP automatically.

## Part 7 — Troubleshooting

### wg show returns nothing on the tablet

The tunnel service is not running. Open WireGuard GUI on the tablet, check if
`EcareAfrica` appears in the list. If it does, click **Activate**. If not, go
back to wizard Step 3 and click **Save & Activate** again.

### "The system cannot find the file specified" error

The WireGuard service could not read the config file. This happens when the bridge
is not running as Administrator. Restart the bridge as admin (right-click → Run as
administrator) and try again.

### "Unable to import configuration: \ufeff[Interface]" error in WireGuard GUI

The config file was written with a BOM (Byte Order Mark). This is fixed in the
latest tablet code. Pull the latest version:
```bash
git pull origin Testing-Branch
```
Then regenerate the config by going through wizard Step 3 again.

### Server public key shows "Not found" in portal

Run on the server:
```bash
# Check if the key file exists
cat /etc/wireguard/server_public.key

# If it shows the wrong key (different from wg show), restore it:
grep PrivateKey /etc/wireguard/wg0.conf | awk '{print $3}' > /etc/wireguard/server_private.key
cat /etc/wireguard/server_private.key | wg pubkey > /etc/wireguard/server_public.key
cat /etc/wireguard/server_public.key
# Must match what wg show reports as the public key
```

### Handshake is old (over 3 minutes)

WireGuard sends a keepalive every 25 seconds. If the handshake is older than
3 minutes, the tablet lost its connection. Check:
1. Is the tablet powered on and connected to the internet?
2. Is the WireGuard tunnel still active on the tablet?
3. Did the tablet's public IP change? (The server updates the endpoint automatically
   on each handshake — no action needed)

### Ping from server to tablet fails even with a recent handshake

The server may have ICMP blocked by iptables. Run:
```bash
iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT
iptables -A OUTPUT -p icmp --icmp-type echo-reply -j ACCEPT
```
Note: ICMP is only needed for manual testing. The system works without ping —
it uses TCP port 5000 to pull logs.

## Quick Reference

### Server commands

```bash
wg show                              # see all connected tablets
ping -c 4 10.0.0.X                   # ping a specific tablet
systemctl restart wg-quick@wg0       # restart WireGuard
wg-quick save wg0                    # save peer changes to wg0.conf
cat /etc/wireguard/server_public.key # show server public key
```

### Tablet VPN IPs

| Tablet | VPN IP | Location |
|---|---|---|
| Tablet 1 | 10.0.0.2 | Main Gate |
| Tablet 2 | 10.0.0.3 | (add here) |
| Tablet 3 | 10.0.0.4 | (add here) |

Update this table as you add tablets.

### Key files on the server

| File | Purpose |
|---|---|
| `/etc/wireguard/wg0.conf` | Main WireGuard config — all peers listed here |
| `/etc/wireguard/server_private.key` | Server private key — never share |
| `/etc/wireguard/server_public.key` | Server public key — shown in Super Admin portal |

### Key files on the tablet (bridge app folder)

| File | Purpose |
|---|---|
| `backend/data/wireguard-private.key` | Tablet private key — never leave the tablet |
| `backend/data/wireguard-public.key` | Tablet public key — pasted into Super Admin portal |
| `C:\ProgramData\WireGuard\EcareAfrica.conf` | Active WireGuard tunnel config |
